# 会话文件错误隔离

会话目录中的单个文件损坏、不兼容、冲突或暂时不可读时，Agent 仍应正常启动，并允许用户新建会话或打开其他健康会话。问题文件保留在会话列表中，由 TUI 显示原因和可执行操作。

本文只规定当前会话 JSONL 文件的处理方式，不提供旧格式兼容、数据迁移或会话格式版本演进方案。`--collect-permission-gaps` 的清理由独立任务处理。

## 分层职责

| 层级 | 职责 |
|---|---|
| `SessionStore` | 逐文件读取和校验；将单条错误转换为会话摘要、问题类型和操作能力；管理写租约 |
| Core | 执行正常打开或强制打开，并复用既有会话恢复流程 |
| TUI | 展示问题标识和诊断信息；只提供 Store 声明为可用的操作 |

会话格式和业务规则仍由 `SessionStore` 检查。Core 和 TUI 不根据错误消息推断行为，而是读取 `SessionCapabilities`。

## 问题类型与行为

| 标识 | 判定条件 | 正常打开 | 强制打开 |
|---|---|---:|---:|
| `[不兼容]` | JSON 合法，但记录类型不在当前 `SessionRecord` 集合中 | 否 | 是 |
| `[内容损坏]` | 中间行不是合法 JSON，或已知记录未通过字段校验 | 否 | 否 |
| `[未完整写入]` | 最后一行没有换行且不是合法 JSON | 是 | 否 |
| `[ID 冲突]` | 多个文件声明相同的会话 ID | 否 | 否 |
| `[读取失败]` | 文件、文件状态或占用状态无法读取 | 否 | 否 |
| `[使用中]` | 其他 Agent 持有该会话的写租约 | 否 | 否 |

`[使用中]` 会关闭该条目的其他操作能力。TUI 将没有任何可用操作的条目置为禁用，但仍显示条目及错误详情。

### 强制打开不兼容会话

强制打开只适用于同时满足以下条件的会话：

1. 文件头有效；
2. 已识别记录中包含模型记录和视图记录；
3. 除未完整尾行外，唯一的问题是存在未知记录类型；
4. 会话 ID 不冲突，且没有被其他 Agent 占用。

Store 获取原会话的写租约后重新检查文件，忽略当前程序不认识的记录，并将已识别记录交给正常的 Core 会话恢复流程。打开的是原会话，不创建副本；未知记录不迁移、不删除，后续记录继续追加到原文件。旧权限记录不会被解释为当前权限设置，用户可以重新选择权限预设和审核方式。

强制打开不会使文件变成兼容格式。当前实例可以继续追加记录，但不能执行会重写整个文件的历史回退；该文件在下次启动时仍会显示 `[不兼容]`，需要再次强制打开。

### 未完整尾行

只有文件末尾没有换行且最后一行无法解析为 JSON 时，才判定为未完整写入。Store 读取时忽略该行，使会话可以正常打开；下一次追加前，在写租约内将文件截断到最后一个完整换行处。

如果最后一行是合法 JSON，只是缺少末尾换行，Store 会保留该记录，并在追加新记录前补充分隔换行。完整但不兼容的 JSON 记录同样不会被截断。

## 问题定义与运行时校验

`packages/core/session-issues.ts` 集中声明会话问题。`SessionIssueCode` 从定义表生成，业务内部通过 `create()` 创建问题，由 TypeScript 检查 code；从会话摘要缓存等外部数据读取字符串时，通过 `has()` 做运行时校验。

业务内部不需要重复做运行时检查。运行时校验只用于跨越磁盘、RPC 或插件等不受 TypeScript 类型系统约束的边界。

## 隔离边界

`SessionStore.list()` 分别处理每个 JSONL 文件。单个文件的 `stat`、读取、解析、字段校验或占用状态检查失败时，只影响对应条目。会话摘要索引是可重建缓存，读取或更新失败也不能阻止会话文件继续使用。

会话目录本身不可访问属于 Store 级故障，不伪装成某个条目错误；TUI 会报告命令失败并保持启动流程，供用户修复环境或重试。当前写入失败同样应使当前操作失败，不能被条目隔离逻辑吞掉。

这套实现不是所有持久化业务的通用 Catalog，也不声明能够通过静态扫描阻止未来代码绕过约束。新的目录型 Store 仍需根据自身数据语义定义问题和操作能力，并通过故障注入测试证明：坏条目可见，健康条目仍可列出和使用。
