# 权限系统使用说明

本文说明 Aizen 的权限系统：它在什么时候介入、依据什么做判断、你可以怎么配置它，以及它管不到的地方。

阅读本文不需要任何技术背景。面向开发者的实现细节另见[《权限系统实现规格》](./spec.md)，当前内置规则具体能识别什么见[《权限系统内置分类器说明》](./classifier.md)。

---

## 1. 它是什么

Agent 在替你工作时会执行命令：读文件、改文件、联网下载、安装依赖。权限系统在每次执行**之前**介入，判断这条命令会做什么，再按你的设置决定是直接执行、问你一声，还是拒绝。

**它是防误操作机制，不是安全沙箱。** 它防的是"Agent 自作主张执行了一条你不希望它执行的命令"，而不是"有人蓄意攻击你的电脑"。这个区别决定了它能做什么、不能做什么，第 6 节会具体说明。

它的行为遵循三条原则，优先级从高到低：

1. **拿不准就问你**，绝不因为看不懂而放行；
2. 能自动判断的就不打扰你；
3. 能用固定规则解决的，不动用 AI。

---

## 2. 两个设置项

这是全文最重要的一节。权限系统的行为由两个互相独立的设置共同决定，它们回答两个不同的问题：

| 设置项 | 回答的问题 |
|---|---|
| **权限预设** | 哪些事情需要管？ |
| **审核方式** | 需要管的时候，谁来管？ |

只理解其中一个，就会对系统行为产生误解。下面分别说明，第 2.3 节说明它们如何配合。

### 2.1 权限预设：哪些事情需要管

系统把 Agent 的行为归成若干类（读工作区文件、联网发送数据、修改系统设置等，完整清单见第 4 节）。权限预设为每一类行为指定一种处理方式：

| 处理方式 | 含义 |
|---|---|
| **放行** | 直接执行，不打扰任何人 |
| **优先AI审核** | 交给 AI 判断，AI 说了算 |
| **必须人工** | 需要人来决定 |
| **拒绝** | 不执行 |

系统提供四档预设，你可以随时为当前对话切换：

- **plan（只读）**：可以查看，不能改动。所有修改、发送、安装类操作一律拒绝，连问都不问。选了这一档，就可以确信这次对话不会改动你的任何东西。
- **edit（编辑，推荐）**：工作区内的读写自由进行；碰到你的个人目录、系统目录、凭据文件，或者要往外发数据，会拦下来。日常开发用这一档。
- **all-right（全放开）**：除极少数绝对禁止的行为外，全部放行。
- **custom（自定义）**：你自己为每一类行为指定处理方式。这是应用级设置，所有对话共用。

各档的具体配置见第 5 节。

### 2.2 审核方式：需要管的时候，谁来管

预设判定"这件事需要管"之后，由审核方式决定实际怎么处理：

| 审核方式 | 行为 |
|---|---|
| **完全人工** | 每一条都问你。默认值 |
| **AI 代审** | 让 AI 替你决定放行还是拒绝 |
| **AI 代审（可弃权）** | 让 AI 决定，但 AI 拿不准时仍然问你 |
| **自动放过** | 不问，全部放行 |
| **自动拒绝** | 不问，全部拒绝 |

后两种用于你不在电脑前的场景：让 Agent 后台跑一段时间，或者在自动化流程里运行。

### 2.3 两者如何配合

关键规则有两条，请务必理解：

**规则一：AI 只处理「优先AI审核」这一类，不碰「必须人工」。**

这是"优先AI审核"和"必须人工"的唯一区别。你可以把联网下载设为「优先AI审核」、把读取凭据文件设为「必须人工」，这样日常的下载操作由 AI 放行，而一旦有人要碰你的密钥，一定会亲自问到你。

**规则二：「自动放过」和「自动拒绝」对两类都生效，包括「必须人工」。**

这一条容易误解，请特别注意：

> 选择「自动放过」之后，**标记为「必须人工」的操作也会被自动放行**。

因为这两个选项的含义是"我不在场"，而不在场时没有人可以审核。它们是全局开关，会覆盖掉「必须人工」的要求。

所以：

- 想完全放开：预设选 **all-right**，或审核方式选 **自动放过**。两者都能达到目的。
- 想让 Agent 无人值守但仍受约束：预设选 **plan** 或 **edit**，审核方式选 **自动拒绝**——这样它只能做预设中标记为「放行」的事，其余全部拒绝。
- **不要**在需要约束的场景下选「自动放过」，那等于全放开。

下表是完整的组合行为：

| 审核方式 ＼ 预设判定 | 放行 | 优先AI审核 | 必须人工 | 拒绝 |
|---|---|---|---|---|
| 完全人工 | 执行 | 问你 | 问你 | 拒绝 |
| AI 代审 | 执行 | AI 决定 | 问你 | 拒绝 |
| AI 代审（可弃权） | 执行 | AI 决定或问你 | 问你 | 拒绝 |
| 自动放过 | 执行 | **执行** | **执行** | 拒绝 |
| 自动拒绝 | 执行 | **拒绝** | **拒绝** | 拒绝 |

注意最后两行：无论选哪种审核方式，**预设中标记为「放行」的仍然执行、标记为「拒绝」的仍然拒绝**。审核方式只影响中间那两类。

## 3. 审核时你会看到什么

当一条命令需要你决定时，界面会展示：

- **命令原文**——实际将要执行的内容；
- **Agent 声明的意图**——它认为自己在做什么、为什么需要这条命令；
- **系统的判断**——这条命令属于哪几类行为，以及判断依据（例如"目标路径位于凭据目录"）；
- **命中的规则**——你当前的预设中哪一条把它拦了下来。

你可以批准或拒绝，并写下理由。**你的决定无条件生效**，不受任何规则约束。

如果你拒绝，Agent 会收到一条说明，包含被哪条规则拦下、以及你写的理由。它会据此调整做法，或者告诉你它做不到。

---

## 4. 系统能识别哪些行为

系统用 12 个固定的标签描述行为。一条命令可以同时命中多个标签，此时按其中**最严格**的一个处理。

**文件操作**（按位置区分）：

| 标签 | 含义 |
|---|---|
| `read-workspace` | 读取工作区内的文件 |
| `read-home` | 读取你的个人目录中的文件 |
| `read-system` | 读取系统目录中的文件 |
| `read-sensitive` | 读取凭据类文件（密钥、令牌、配置密码等） |
| `edit-workspace` | 修改工作区内的文件 |
| `edit-home` | 修改个人目录中的文件 |
| `edit-system` | 修改系统目录中的文件 |
| `edit-sensitive` | 修改凭据类文件 |

一个文件可以同时属于多类。例如你的工作区在个人目录下，那么读取其中一个文件会同时命中 `read-workspace` 和 `read-home`；而 `~/.ssh/id_rsa` 会同时命中 `read-home` 和 `read-sensitive`。**多个标签取最严的处理方式**，所以位置越敏感，保护越强，不需要额外的优先级规则。

修改包括创建、改写、移动和**删除**。

**其他行为**：

| 标签 | 含义 |
|---|---|
| `network-fetch` | 从网络获取数据（含 `npm install` 这类隐含的下载） |
| `network-send` | 向网络发送数据（含 `git push` 这类上传） |
| `system-change` | 改变系统状态：安装软件、启停服务、修改全局配置 |

**绝对禁止**：

| 标签 | 含义 |
|---|---|
| `violation` | 命中了绝对不该发生的行为 |

`violation` 与其他标签不同：**它固定为拒绝，任何预设、任何审核方式都无法放行它**。它用于"在任何场景下都不应该发生"的行为，例如删除系统根目录、把私钥内容发送到网络、篡改权限系统自身的配置。

它不用于"危险但有时正当"的行为。例如 `rm -rf ./dist`（删除构建产物）是正常的开发操作，属于 `edit-workspace`，由你的预设决定怎么处理。

### 看不懂的命令

如果系统无法确定一条命令会做什么，它会被标记为**无法判断**，一律**交给人工审核**，绝不自动放行。

典型情况：

- 命令的目标要到运行时才知道，例如 `rm -rf $BUILD_DIR`（`$BUILD_DIR` 的值是什么，事前看不出来）、`rm -rf *`（`*` 会展开成哪些文件，取决于当时目录里有什么）；
- 要执行的代码在命令里看不见，例如 `curl https://example.com/x.sh | bash`——这条命令下载一段脚本并立即执行，而脚本内容在执行前并不存在，无从审核。

在 all-right 档下，这类命令也会被放行。这是"全放开"的应有之义，请在了解后果的前提下使用。

### 直接拒绝、无法放行的几种写法

有极少数命令会被**直接拒绝，且不提供任何放行入口**，因为它们会破坏系统判断命令的能力本身：

- 定义函数或别名——可以让一个看似无害的命令名实际执行别的操作，之后所有同名命令的判断都不再可信；
- `eval`——把一段文字当作命令执行，要审核的内容在执行前不存在；
- `source`——把另一个文件的内容并入当前环境执行。

这几种写法在正常开发中极少直接使用，Agent 遇到时会改用其他方式。

## 5. 各档预设的具体配置

`unknown` 表示系统无法判断的命令。`violation` 固定拒绝，不在表中。

| 行为 | plan | edit | all-right |
|---|---|---|---|
| 读取工作区 | 放行 | 放行 | 放行 |
| 读取个人目录 | 优先AI审核 | 放行 | 放行 |
| 读取系统目录 | 优先AI审核 | 放行 | 放行 |
| 读取凭据文件 | 必须人工 | 必须人工 | 放行 |
| 修改工作区 | 拒绝 | 放行 | 放行 |
| 修改个人目录 | 拒绝 | 优先AI审核 | 放行 |
| 修改系统目录 | 拒绝 | 必须人工 | 放行 |
| 修改凭据文件 | 拒绝 | 必须人工 | 放行 |
| 网络获取 | 优先AI审核 | 放行 | 放行 |
| 网络发送 | 拒绝 | 优先AI审核 | 放行 |
| 改变系统状态 | 拒绝 | 必须人工 | 放行 |
| 无法判断 | 必须人工 | 必须人工 | 放行 |

几点说明：

- **plan 档不提供人工放行入口**。所有修改类操作直接拒绝，不会问你。这样"选了 plan 就不会有任何改动"是一句可以确信的话。如果中途需要修改文件，在对话里切换到 edit 档即可。
- **edit 档的读取几乎全部放行**。构建工具会持续读取缓存目录和系统头文件，如果设为人工审核，会频繁打断到无法工作。
- **edit 档允许网络获取**是为了 `npm install`、`git pull` 这类日常操作。下载到的内容如果要被执行，会落入"无法判断"从而转人工，这一层仍然拦得住。

## 6. 它管不到的地方

以下三条是系统的固有边界，请在依赖它之前了解清楚。

### 只保护命令里写明的路径

系统通过工具参数、命令文本和内置分类器掌握的命令语义判断它会碰哪些文件。像 `npm install` 这样语义明确的命令，可以识别出网络获取和安装目标写入；但如果一条命令没有写出某个路径，分类器也无法从命令语义可靠推导，系统就看不见该路径。

例如 `npm install` 会读取你的 `~/.npmrc`（其中可能存有发布令牌），但这个路径不出现在命令里，也不能仅凭当前参数可靠确认，因此不会被识别为"读取凭据文件"。

**因此"凭据文件受保护"的准确含义是：路径明确出现在工具参数或命令中，或其位置能由已知命令语义可靠推导时受保护。**

### 执行本地脚本后就管不到了

当 Agent 执行 `./build.sh`、`node script.js`、`make` 这类命令时，权限系统只能判断"要执行某个脚本"，**无法看到脚本内部会做什么**。一旦放行，脚本里的所有操作都不再经过任何检查。

这类命令通常会被标记为"无法判断"从而询问你。**你在批准时，实际批准的是脚本内部的全部行为**，而不只是"运行一个脚本"这个动作。

### 假定你的终端配置是可信的

系统假定你自己的 shell 配置文件（`.bashrc` 之类）没有被篡改。如果有人事先在其中埋了伪装命令，权限判断可能被绕过。

这个假定是合理的：能修改你配置文件的人，本来就能直接执行任意命令，不必绕道欺骗权限系统。**这也再次说明这是防误操作的工具，不是防攻击的工具。**

## 7. 记录

每一次权限判定都会被记录，这项记录常驻，不可关闭。

- **对话记录**中保存 Agent 当时看到的信息：行为类别、命中规则、拒绝理由。
- **审计文件**保存完整的判定过程：谁做出的判断、依据什么、命中哪条规则、AI 或人的决定和理由。

审计文件**只保存在本地，不会上传**。写入前会遮蔽命令中的密钥、令牌等敏感内容，同时保留足够的信息以便日后查清当时为什么这样判定。文件会按大小自动轮转，你可以随时查看或删除。
