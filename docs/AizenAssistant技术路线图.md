# AizenAssistant 技术路线图

本文档面向项目负责人和后续维护者，用于确认产品目标、当前边界、后续顺序和阶段完成条件。各阶段的接口与实现方案在进入该阶段时另行设计。

## 1. 产品目标

AizenAssistant 是基于 pi SDK 的 AI Agent 应用，提供可独立使用的终端界面，并逐步建设重点打磨的桌面界面。

项目需要完成两项核心定制：

- **每轮额外消息**：请求模型前可生成额外消息。所有实际发送的消息均写入会话；标记为仅当轮使用的消息不进入后续请求。
- **视图式上下文**：系统提示词、`AGENTS.md` 和 Skill 由当前视图提供，不按工作目录层级隐式加载。视图可在两轮之间切换。

M0 至 M2 已完成，当前应进入 M3。

| 能力 | 当前状态 |
| --- | --- |
| 仓库治理与自动检查 | 已完成 |
| pi SDK、OpenTUI 与 Windows x64 单文件构建验证 | 已完成 |
| 无界面 TypeScript 核心与 pi adapter | 已完成 |
| 多轮 TUI、会话保存与恢复、认证、模型切换 | 已完成 |
| 流式输出、工具展示、中止、上下文压缩记录 | 已完成 |
| 终端原生滚动、助手回复和工具组折叠 | 已完成 |

当前 TUI 固定使用空视图，每轮记录 `viewId: null`。折叠操作会全量回放会话，并清除当前终端标签页原有的 scrollback。

## 3. 架构边界

```text
当前：
自研 TUI ── TypeScript 核心 ── pi adapter ── pi SDK

规划：
Vue 桌面界面 ── Tauri / Rust ── JSONL ── core-sidecar ── TypeScript 核心
```

| 模块 | 职责 | 状态 |
| --- | --- | --- |
| `packages/core` | 会话、模型、结构化记录和前端无关的业务状态 | 已实现 |
| `packages/pi-adapter` | 隔离 pi SDK 类型、事件和资源加载接口 | 已实现 |
| `packages/tui-kit` | 隔离 OpenTUI，提供终端渲染与输入组件 | 已实现 |
| `core-sidecar` | 将核心命令和事件映射为版本化 JSONL | M4 实现 |
| Tauri / Rust | 管理 sidecar 生命周期并转发字节 | M5 实现 |
| Vue 前端 | 承载桌面交互和界面状态 | M5 起实现 |

必须保持以下约束：

- 业务逻辑集中在 TypeScript；Rust 不处理会话、模型、视图或消息规则。
- TUI 与桌面界面共用同一核心，不分别实现业务流程。
- pi 只能由 `packages/pi-adapter` 使用，OpenTUI 只能由 `packages/tui-kit` 使用。
- pi 和 OpenTUI 锁定精确版本；升级前审阅破坏性变更，并使用独立 PR。
- 不修改 pi 源码，不使用 pi 会话格式作为产品数据格式。
- Windows x64 首发产物不要求用户安装 Node 或 Bun。

## 4. 数据与上下文规则

当前数据目录包含：

```text
data/
├─ auth.json
├─ models.json
└─ sessions/
   └─ <工作目录名称>-<路径哈希>/
      └─ <会话 UUID>.jsonl
```

M3 将增加 `views.json`，保存视图 ID 与视图目录的对应关系。

会话和上下文必须满足以下规则：

- 会话使用 AizenAssistant 自有的版本化 JSONL 格式；pi 会话只存在于内存中。
- 会话保存每轮实际发送的输入、助手消息、工具结果和结束状态。
- 图片以 Base64 直接写入消息，不建立附件目录。
- 上下文压缩只影响后续请求，不删除或改写原始记录。
- 会话只保存视图 ID，不保存系统提示词、`AGENTS.md` 或 Skill 的内容副本。
- 恢复会话时按当前程序版本和当前视图重新装载运行时资源。

### M0 —— 仓库治理

建立版本约束、自动检查、PR 流程和主分支防误操作措施。

**完成标志：** 仓库配置检查、格式检查、静态检查、类型检查和测试进入统一验证流程。

### M1 —— 架构可行性验证

验证 pi SDK、OpenTUI、WASM 和原生依赖可以共同编译为 Windows x64 Bun 单文件。

**完成标志：** 编译产物可在无 Node、无 Bun 环境加载依赖，并通过 pi provider 完成模型请求链路。

### M2 —— 核心与自举 TUI

建立无界面核心、pi adapter、OpenTUI 适配层和可独立使用的终端应用。

**完成标志：** TUI 支持多轮对话、会话恢复、模型与认证、流式输出、工具执行、中止、折叠和 `--plain` 模式；会话使用自有格式保存。

### M3 —— 上下文定制

实现两项核心定制，并继续通过 TUI 验证真实行为。

范围：

- 读取和校验 `data/views.json`。
- 新建或恢复会话时选择视图，并允许在两轮之间切换。
- 每轮重新读取当前视图的系统提示词、`AGENTS.md` 和 Skill。
- 请求前生成零条或多条额外消息，并在发送前写入会话。
- 通过 `useLater` 明确额外消息是否进入后续请求。

完成条件：

- 仅当轮消息进入当前请求和会话记录，但不进入下一轮请求。
- 修改或切换视图后，下一轮使用目标视图的最新内容。
- 会话恢复后按保存的视图 ID 装载资源，不依赖工作目录中的同类文件。
- 视图不存在、路径失效或内容无效时阻止发送请求，并给出明确错误。
- 多轮人工观察与自动测试得到一致结果。

### M4 —— 桌面进程边界

建立版本化 JSONL 协议和 `core-sidecar`，复用现有核心。

**完成标志：** 无界面客户端可通过协议完成会话创建、请求、中止和恢复；JSONL 不在 `U+2028` 或 `U+2029` 处分帧；sidecar 异常退出可被检测和恢复；协议进程可构建为无需外部运行时的 Windows x64 产物。

### M5 —— 桌面最小闭环

建立 Vue、Tauri 和 `core-sidecar` 的真实运行链路。

**完成标志：** 桌面应用可完成一次真实模型请求和中止；能够报告 sidecar 启动失败、协议错误和异常退出；关闭应用后不残留 sidecar 进程。

### M6 —— 桌面核心功能

在桌面界面中提供 TUI 已验证的核心能力。

**完成标志：** 会话、认证、模型、视图、多轮消息、工具执行、中止和恢复均可从桌面界面使用，并与 TUI 产生一致的核心记录。

### M7 —— 桌面体验完善

集中处理信息层级、长内容阅读、窗口缩放、输入焦点和状态反馈。

**完成标志：** 长会话、长工具输出、中文输入和窗口缩放不影响主要操作；项目负责人可用桌面界面完成日常多轮任务。

### M8 —— Windows 分发验收

固化 Windows x64 的构建、打包、升级和数据目录行为。

**完成标志：** 产物可重复构建，并在无 Node、无 Bun 的干净环境运行；安装、升级和卸载不会静默改变或遗留产品数据。

## 6. 跨阶段验收

- 核心规则使用自动测试验证；涉及模型上下文的行为还必须进行多轮人工观察。
- JSONL 必须覆盖边界字符、半包、异常输出和进程退出场景。
- 分发必须在无 Node、无 Bun 的干净 Windows x64 环境验证。
- 每个里程碑通过独立 Draft PR 交付，由项目负责人完成设计确认和真实环境验收。
- 未完成验证时不得宣称阶段完成；需要改变架构或分发形态时先停止实施并重新确认。
